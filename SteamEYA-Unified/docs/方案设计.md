# 「SteamEYA 一体化上号器」方案设计

> 目标：把 **Steam 上号器**、**云游戏上号器（原神/星穹铁道/异环/哔哩哔哩）**、**聊天室** 三套客户端与服务端，
> 合并为「一个客户端 + 一套统一账号」，界面统一在 Steam 上号器的界面风格内，操作逻辑统一按 Steam 上号器的习惯来做。
> 本文只做方案设计（功能 / 界面 / 操作逻辑），不修改任何代码。

---

## 一、现状盘点与关键前提

### 1.1 已有资产

| 模块 | 客户端技术栈 | 服务端技术栈 | 地址/端口 | 核心能力 |
|---|---|---|---|---|
| Steam 上号器 | C# **WinUI3**（.NET 10） | Python **FastAPI + SQLite** | `47.104.210.199:6967` | EYA 令牌上号、远程账号分发（卡密/账号自动获取）、优先分/等级/冷却查询、历史账号、一键配装、创意工坊清理、多语言 |
| 云游戏上号器 | Python **tkinter + Selenium** | Python **Flask + SQLite** | `47.104.210.199:6966` | 浏览器抓 Cookie / 注入 Cookie 一键上号、Cookie 有效性检测、Cookie 自动续期、云端上传/下载 Cookie、登录记录上报 |
| 聊天室 | Web（**原生 HTML/CSS/JS**） | Node.js **Express + ws + node:sqlite** | `:8897` | 群聊/私聊、图片/视频/文件、表情包共享库、@提及、撤回、已读未读、搜索聊天记录、头像/昵称、邀请码注册、WebSocket 实时、PushPlus 推送、管理后台 |

### 1.2 关键前提（已确认）

- **Steam 上号器客户端源码取自上游开源仓库**：<https://github.com/hvh-software/OpenSteamEYA>
  （压缩包内 `Steam上号器客户端/` 仅有 [SteamEyaWinUI.sln](file:///workspace/extracted/项目合集/Steam上号器客户端/SteamEyaWinUI.sln)、README、构建脚本与安装器配置，无 `.cs/.xaml/.csproj`；以该仓库源码作为 WinUI 外壳基线，在其上扩展。）
- **聊天室集成**：在线状态用 **WebView2** 内嵌现有 Web 前端；离线状态方案见 4.6。
- **统一后端**：**单 FastAPI 网关合并**（账号中心 + 三业务模块，共享统一 users 与 JWT）。
- **局域网发现**：**自动发现（UDP 广播/mDNS）+ 手动填 IP 兜底**。

> 客户端外壳沿用 WinUI3（源自上游仓库），结构见第三～六章。

### 1.3 三套账号体系互不相通（必须统一）

- Steam 服务端：`users(username, sha256+salt)` + JWT（7 天）
- 云游戏服务端：`users(username, sha256+固定盐)` + 自签 HMAC token
- 聊天室：`users(username, scrypt+salt)` + `sessions` cookie（30 天）

需求是"**一个账号登录即可使用全部功能**"，因此必须引入**统一账号中心**。

## 二、设计目标

1. **单客户端**：只装一个软件；打开先显示登录页，登录成功进入主界面；主界面内不再有第二次登录。
2. **统一账号**：一套用户名/密码，同时用于上号与聊天。
3. **界面统一且更美观**：全部功能收进 Steam 上号器界面风格；统一设计语言（配色、圆角、字体、动效、明暗主题）。
4. **操作逻辑统一**：云游戏的操作向 Steam 靠拢（一键化、状态面板化、历史化），不沿用云游戏那套"抓取→保存→上号"的繁琐流程。
5. **联网/离线自适应**：
   - 有网：走聊天室在线聊天 + 上号云端能力。
   - 无网：**免登录**进入，提示「检测到无网络链接，已转换至离线模式」，界面**只保留「局域网功能」**（即聊天室界面），数据本地存储；首次使用需输入昵称以区分用户。
   - 恢复联网：本地聊天记录自动上传服务器并同步；保留聊天室原有文件发送能力，局域网内可直接互传。

## 三、总体架构

```
┌────────────────────────── 客户端（Windows 单 App） ──────────────────────────┐
│  外壳：C# WinUI3（沿用 Steam 上号器界面与交互）                                  │
│                                                                              │
│  ┌─ 登录页 ─┐   ┌─────────────── 主界面（侧边导航）───────────────┐            │
│  │ 统一账号 │→  │ ① Steam 上号 │ ② 云游戏上号 │ ③ 聊天室 │ ④ 设置/关于 │        │
│  └──────────┘   └───────────────────────────────────────────────┘            │
│                                                                              │
│  内嵌能力：                                                                    │
│   • 云游戏引擎：Python(Selenium) 子进程 / 本地 FastAPI（打包为内部服务）          │
│   • 聊天室：WebView2 内嵌现有 Web 前端（复用 index.html/app.js/style.css）       │
│   • 本地服务：离线时在回环/LAN 起本地聊天服务 + 本地 SQLite                         │
└──────────────────────────────────────────────────────────────────────────────┘
                                   │ HTTPS / WSS
┌────────────────────────────── 服务端（统一后端）──────────────────────────────┐
│  统一账号中心（Auth Gateway）：users 表 + JWT 签发/校验                          │
│  业务模块（可做单进程多路由，也可保留多服务共同信任 JWT）：                         │
│   • Steam 账号分发 API（原 6967）                                              │
│   • 云游戏 Cookie 服务 API（原 6966）                                          │
│   • 聊天室 HTTP + WS（原 8897）                                                │
│  数据：统一 users；分库/分表保存 accounts、cookies、messages 等                   │
└──────────────────────────────────────────────────────────────────────────────┘
```

**推荐落地方式**
- 客户端外壳保持 **WinUI3**（Steam 上号器现有观感）。
- 云游戏能力**不重写**：保留 Python（Selenium 抓/注入 Cookie）逻辑，封装成**本地服务/子进程**，客户端通过本地 HTTP 调用；打包时用 PyInstaller 打进安装包。
- 聊天室**不重写**：现有 Web 前端已经较完整美观，直接 **WebView2 内嵌**；在线时连远端，离线时连本机服务。
- 服务端优先做 **"统一账号中心 + 三个业务模块信任同一 JWT"**，避免一次性大重写。

## 四、功能设计

### 4.1 统一登录与账号
- **登录页**（软件首个界面）：用户名 + 密码，支持注册。
- 登录成功 → 拿统一 JWT → 写入本地安全存储（DPAPI/加密文件），后续自动登录。
- 主界面**移除**现有"远程账号登录"入口（README 里描述的 LoginPage 内嵌登录逻辑删除）。
- 统一账号可访问：Steam 账号分发、云游戏 Cookie 云同步、聊天室。

### 4.2 网络模式
- 启动即做**连通性探测**（请求统一后端 `/health`，超时判定）。
- **在线模式**：登录 → 主界面全功能。
- **离线模式**：不要求登录，弹提示「检测到无网络链接，已转换至离线模式」→ 主界面**只显示「局域网（聊天）」**，其余模块置灰/隐藏；首次进入要求输入**昵称**（本地保存，用于区分聊天用户）。

### 4.3 Steam 上号模块（保持现有逻辑）
沿用现状不动：
- 手动模式：账户名 + EYA 令牌 → 登录本机 Steam。
- 自动模式：输入卡密 → 从服务器解析账号 → 一键登录。
- 右侧状态面板：Steam64 ID、令牌有效期、可用状态、CS2 优先分/等级/冷却。
- 历史账号管理：搜索、批量导入/导出、批量查询、筛选（VAC/优先分/国服/分组）。
- 一键配装、清理创意工坊订阅、自动更新、多语言。

### 4.4 云游戏上号模块（迁移 + 按 Steam 逻辑改造）
**迁移沿用**（来自 [main.py](file:///workspace/extracted/项目合集/云游戏上号器客户端/main.py) / [browser_driver.py](file:///workspace/extracted/项目合集/云游戏上号器客户端/browser_driver.py)）：
- 支持 4 个目标：原神 / 星穹铁道 / 异环 / 哔哩哔哩（`vendor`: mihoyo / wanmei / bilibili）。
- 浏览器抓 Cookie、combo_token 抓取、本地加密保存（PBKDF2+Fernet，见 [cookie_crypto.py](file:///workspace/extracted/项目合集/云游戏上号器客户端/cookie_crypto.py)）。
- Cookie 有效性检测、免费时长查询、Cookie 自动续期。
- 云端上传/下载（服务端 Fernet 主密钥加密，见 [app.py](file:///workspace/extracted/项目合集/云游戏上号器服务端/app.py)）。
- 每个游戏独立 profile，可同时上号多个游戏。

**逻辑改造（对齐 Steam 习惯）**：
- 云端（自动）模式：登录后**直接拉取该账号已上传的 Cookie → 一键上号**，无需手填服务器地址/密码（内置）。
- 本地（手动）模式：选择本地加密文件 + 密码 → 一键上号。
- "抓取 / 更新 Cookie" 收敛为**独立入口按钮**（更新令牌），而非主流程步骤。
- 状态面板化：显示每个游戏的 Cookie 状态、账号昵称/UID、剩余免费时长、最近上号时间（对齐 Steam 右侧面板）。
- 切换游戏即切换目标，账号信息与状态随之刷新（对齐 Steam 的逻辑）。

### 4.5 聊天室模块（联网）
复用 [server.js](file:///workspace/extracted/项目合集/聊天室服务器源码/server.js) 与 Web 前端全部能力：
- 群聊大厅 + 私聊；图片/视频/文件（单文件 50MB）；表情包共享库；@提及；撤回（2 分钟内）；已读/未读；聊天记录搜索；头像/昵称/改密；系统通知横幅；邀请码注册；管理后台。
- WebSocket 实时（`/ws`），心跳保活。

### 4.6 离线（局域网）聊天模块（无网）
- 界面：**沿用聊天室界面**，只保留「局域网功能」。
- 身份与映射规则（**关键**）：首次进入要求输入**昵称**；该昵称将作为联网后的账号映射依据 → 离线消息归属到**与昵称同名的在线账号**，以保证聊天记录正常同步。输入页需显著提示：
  > 务必使用和在线聊天一模一样的用户名，以保证后续聊天记录正常同步！！
- 数据存储位置（**重要**）：离线聊天数据保存在**软件安装所在盘**的目录下（如 `<AppDir>\data\`），**不落 C 盘**。
  - 若软件被装在 C 盘：启动时弹窗让用户**另选一个非 C 盘目录**作为数据目录，并记住该选择。
- 局域网互传：本机起**本地聊天服务绑定 LAN 网卡**，同网段其他实例自动发现（UDP 广播/mDNS，见 6.5）并连接，实现聊天与文件互传，不依赖外网。
- 恢复联网：按 6.4 把本地产生的会话/消息**幂等同步**到服务器，并保留原有文件发送能力。

### 4.7 设置 / 关于
- 语言（沿用 Steam 的多语言）、主题（明/暗）、聊天通知开关、服务器地址（高级）、自动更新、许可证/关于。

### 4.8 云存档模块（新增）
支持 **植物大战僵尸（pvz）** 与 **我的世界（minecraft）** 两种游戏存档的云端备份与共享。

**存档目录**：`C:\ProgramData\PopCap Games\PlantsVsZombies\pvzHE\yourdata`（植物大战僵尸）。

**界面与列表**
- 顶部选择游戏；列表显示该用户在该游戏**历史上传过的所有存档**，按**日期命名**（如「2026年10月11日14:32」）。
- 无记录时显示「你还没有上传过存档喵~」。

**核心操作**
- **自动备份**：自动压缩 `yourdata` 文件夹并上传服务器。
- **下载备份**：选中存档后下载并**解压回 `yourdata` 目录**以还原。
- **拖拽上传**：可直接把 `.zip` 拖入本页上传；**严格限制仅允许单个压缩包**（拖入文件夹 / 多个文件 / 非 zip 一律拒绝）。
- **右键菜单**（对单个存档）：备注 / 下载到指定文件夹 / 还原此存档 / 共享存档。
- **多选共享**：多选存档后点「共享存档」，即全员共享。

**共享存档**
- 所有用户可在该游戏的「共享存档」中看到：**哪位用户、什么时间**的存档。
- 共享存档的**备注跟随上传者自己存档列表里的备注**（同一字段）。

**我的世界差异**
- 暂不支持自动上传：把「自动备份」按钮**置灰**，鼠标悬停提示「该功能暂不可用 试着拖入存档压缩包上传吧」；上传仍可通过拖入 zip 完成。

**服务端接口**（/api/save/*）
| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/save/upload` | POST(multipart) | 上传单个 .zip（game/name/remark/source） |
| `/api/save/list` | GET | 我的存档（按创建时间倒序） |
| `/api/save/shared` | GET | 该游戏的全部共享存档（含上传者） |
| `/api/save/download` | GET | 下载（本人或共享存档） |
| `/api/save/remark` | POST | 修改备注 |
| `/api/save/share` | POST | 共享/取消共享（支持多选） |
| `/api/save/delete` | POST | 删除（支持多选） |

## 六、操作逻辑设计

### 6.1 启动与模式判定
1. 启动 → 探测后端连通性（`/health`，3s 超时）。
2. **在线** → 检查本地 token：
   - 有效 → 直接进主界面；
   - 无效/无 → 显示登录页 → 登录成功进主界面。
3. **离线** → 弹窗「检测到无网络链接，已转换至离线模式」→ 进主界面（仅局域网聊天）；首次需输入昵称。

### 6.2 上号统一逻辑（"Steam 化"）
- 统一心智：**选目标 → 一键上号 → 看状态面板**。
- Steam：手动/自动两种取号方式 → 一键登录 Steam。
- 云游戏：云端一键（自动取已上传 Cookie）/ 本地文件（选手动文件）→ 一键上号云游戏。
- "抓取/更新 Cookie"降级为**维护动作**（放在状态面板或次要按钮），不作为主流程必经步骤。
- 所有耗时操作走后台线程 + 日志区输出（沿用现有 `log_queue` 机制）。

### 6.3 聊天室逻辑
- 在线：登录即用统一账号加入（无需二次输入用户名），通过 WS 收发。
- 发送：文本/图片/文件/表情；@ 通过输入框触发成员选择；撤回限 2 分钟。
- 通知：桌面横幅（沿用现有 Notification 逻辑）。
- 文件：上传到服务器 `/uploads`，按消息引用（沿用现状）。

### 6.4 离线 → 在线 同步逻辑（重点：不丢、不重、按原时间序）
1. 离线期间：所有消息写入本地库，每条记录**真实发送时间 `created_at`（离线当时的本地时间）**，并生成**本机唯一 ID**（`install_id + local_seq`），置 `synced=0`。
2. **账号归属**：离线昵称 = 在线用户名 → 消息归属到**同名在线账号**（见 4.6 提示）。
3. 首次恢复联网：把 `synced=0` 的消息批量上传 → 成功后置 `synced=1`，并记录 `last_synced_seq`。
4. **按原始时间同步（关键）**：上传与服务器入库**一律使用消息的真实 `created_at`，而不是联网/上传时刻**。
   - 服务器以 `created_at` 落库并据此参与排序，时间线保持与离线期间一致；
   - 拉取合并时同样按 `created_at` 排序插入，避免"补录的消息"全部挤到当下。
5. **防重复（关键需求）**：一旦本机（该安装/数据目录）完成过一次离线数据同步，后续任何人再打开软件**不再重新上传已同步消息**。
   - 本地侧：仅上传 `synced=0` 的记录；`synced=1` 直接跳过，第二个用户打开时队列为空 → 不上传。
   - 服务端侧：以 `(install_id, local_msg_id)` 建唯一约束做**幂等去重**，即使重复提交也不会产生重复消息（双保险）。
6. 拉取：同步完本地后，从服务器拉取该账号可见的增量消息（按服务器消息 ID 增量），本地按 `local_msg_id` 与服务器 ID 去重后，**按 `created_at` 归并排序**展示。
7. 失败处理：保留本地队列，`synced` 保持 0，下次联网自动重试（幂等，可安全重跑）。
8. 同步状态文件（`sync_state.json`）与本地库同放**非 C 盘的软件数据目录**（见 4.6）。

### 6.5 文件局域网互传
- 离线时本机启动本地聊天服务，监听 LAN 地址。
- **发现**：优先 UDP 广播/mDNS 自动发现同网段实例；兜底支持手动填对端 IP。
- **传输**：同一局域网内点对点/经对端本地服务直接传文件（不走公网），支持断点续传提示。
- 恢复联网后，文件消息随消息记录同步（大文件可采用"引用 + 按需下载"策略）。

## 九、安全设计
- 统一 JWT + 刷新机制；客户端 token 加密存储。
- 云游戏 Cookie：客户端 PBKDF2+Fernet；服务端 Fernet 主密钥（沿用现状），**强制 HTTPS**。
- 聊天上传：类型/大小白名单（图片/视频/文件，≤50MB）、文件名安全化（沿用 `safeName`）。
- 管理后台权限收敛到统一 admin 标记。
- 离线本地库可做简单加密（可选）。

## 十二、风险与待确认事项

**已确认（本方案已锁定）**
- 客户端源码：取自上游 `hvh-software/OpenSteamEYA`。
- 聊天集成：在线 WebView2，离线本地库 + 局域网。
- 后端：单 FastAPI 网关合并。
- 局域网发现：自动发现 + 手动兜底。
- 离线数据目录：软件所在盘（非 C 盘）；同步幂等防重复。
- 离线账号映射：**离线昵称 = 在线用户名**（输入页强提示）。
- 同步时间口径：**按消息真实发送时间同步与排序**，不用联网时刻。

**仍需注意的风险**
1. **上游仓库与本压缩包服务端是否完全对齐**——需核对 OpenSteamEYA 版本与 `47.104.210.199:6967` 接口字段。
2. **统一账号迁移**——三套用户表合并时同名账号、密码哈希算法不同（sha256/scrypt），需迁移策略（改密/首次登录重置）。
3. **云游戏引擎打包**——Selenium 与浏览器依赖、PyInstaller 体积、杀软误报。
4. **离线数据目录若安装在 C 盘**——需引导用户改到非 C 盘，规则要清晰。
5. **离线昵称必须与在线用户名一致**——已明确按"离线昵称=在线用户名"映射账号；若用户填了不一致的昵称，同步时可能找不到对应账号，需在提示中强约束（见 4.6 提示语），并在同步失败时给出明确引导。
